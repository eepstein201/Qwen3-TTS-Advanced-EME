# Jules' Project Insights: Qwen3-TTS

This document synthesizes findings from `CLAUDE.md`, `README.md`, the commit history, project plans, and development configurations to provide a comprehensive understanding of the Qwen3-TTS project and serve as a reference for autonomous work.

## Project Overview

Qwen3-TTS is a text-to-speech system with voice cloning, built on Qwen3-TTS models. It offers three main modes:
- **Clone Mode:** Clones voices from audio samples (5-15s), with an embedding-only option.
- **Design Mode:** Generates voices from text descriptions.
- **Custom Mode:** Uses 9 premium pre-trained speakers.

The system features a high-concurrency asynchronous FastAPI server, optimized for hardware flexibility:
- **MLX Backend:** For Apple Silicon (macOS).
- **PyTorch Backend:** Standard support (Linux / Intel Mac).
- **vLLM-Omni Backend:** High-speed integration for Linux/NVIDIA setups.

It supports real-time bidirectional audio streaming, LUFS normalization, configurable crossfading, and rate limiting.

## Architecture and Coding Standards

- **Core Engine:** Organized into submodules (`text_processing`, `audio_processing`, `voice_prompt`, `model_loader`, `inference`, `asr`) under `qwen3_tts/core/engine`. Uses facade patterns (`__init__.py`) to expose public functionality.
- **Lazy Imports:** Mandatory! Imports for `torch`, `mlx`, `transformers`, etc., must occur inside functions and never at the module scope to avoid environment conflicts.
- **Configuration:** Managed via `config.json` (accessed via `qwen3_tts/core/config.py`).
- **Web UI & CLI:** Built on Gradio (via `qwen3_tts/interface/ui`) and Click (`qwen3_tts/cli.py`).
- **SOLID Principles:** The project is heavily aligned with clean architecture, even employing a custom analyzer (`tts solid-score`).

## Git and Development Workflow

- **No AI Authorship Attribution:** **NEVER** include `Co-Authored-By`, `Generated by Claude`, or any other AI attribution in commits, code comments, or PR descriptions.
- **Branching:** Work MUST be done on feature branches (`git checkout -b feature/...`). NEVER push directly to `main`. Do not use destructive git commands (`--hard reset`, force-push) without explicit permission.
- **TDD / Testing:**
  - Over 2100 tests. Tests run in any Python environment using `pip install -e ".[test]"`.
  - Use the batch runner (`python tests/run_batches.py` or `make test-batch`) instead of raw pytest to prevent OOM hangs. A CLI hook explicitly warns against running raw pytest for the full suite.
  - Follow Red-Green-Refactor logic for new features and bug fixes.
- **Editing Files:** Prefer editing existing files to creating new ones. Ensure `CLAUDE.md` is updated on architectural or API changes.
