# Qwen3-TTS Project

Text-to-speech system with voice cloning, built on Qwen3-TTS. Three modes: clone (from audio), design (from description), custom (9 premium speakers). Runs on Mac (MLX/torch), Linux, and Google Colab (CUDA).

Features: pyrubberband audio processing (librosa fallback), prosody presets for Custom/Design, x_vector_only_mode for transcript-free cloning (generation + voice-prompt creation), web-UI output folders (Automated Output for generations, Manual Downloads for kept files) with per-row Remove (hard-deletes the file, path-keyed two-step confirm) and Download (copies to Manual Downloads).

### Design Principles

- **Lazy imports everywhere** — neither `torch` nor `mlx` imported at module scope in any file
- **Two conda envs** — `qwen3-tts` (torch) and `qwen3-tts-mlx` (mlx) due to `transformers` version conflict
- **Three separate models** — Clone, Design, Custom are distinct HuggingFace models (~3.5GB torch, ~2.5GB MLX 8-bit each)

## Server API

Base: `http://127.0.0.1:5123`

Public (no auth): `/health`, `/ready`, `/generation-status`, `/queue-status`. `/generation-status` intentionally omits request-content-derived fields (`eta_sec`, `batch_total`, `chunk_total`) — input size must not leak to unauthenticated callers; it exposes only `active`, `cancelled`, coarse `batch_index`/`chunk_index`, `elapsed_sec`. `/health`'s `model_load_errors` redact absolute paths to `<path>` (CWE-209). `/ws` marks `generation_state` active during generation (so `/generation-status` sees WS work) and validates the browser `Origin` against the CORS allowlist before `accept()` (CSWSH defense; absent Origin allowed — auth is the per-message token).

All other endpoints require `Authorization: Bearer <token>` (token from `~/.config/qwen3-tts/.voice_server_token`, legacy fallback `~/.voice_server_token`). JSON routes carry Pydantic `response_model=` contracts in `server/validation.py` (binary routes `/generate-stream`, `/ws`, `/preview-prompt`, `/shutdown` deliberately untyped) — guarded by `tests/test_response_contracts.py`.

**Reverse proxies:** honor `X-Forwarded-For` for client-IP / rate-limit keying only when the direct TCP peer is in the `TTS_TRUSTED_PROXIES` allowlist (comma-separated IPs; loopback default). Set it behind a reverse proxy.

**Rate limits:** `TTS_DISABLE_RATE_LIMITING=1` no-ops every rate-limit decorator (local E2E/CI servers only). Per-limit overrides: `TTS_RATE_LIMIT_{GENERATE,MODEL_OPS,TRANSCRIBE,PROMPT_OPS,CONFIG_OPS,GLOBAL}`. The global pre-auth ceiling (`security.rate_limits.global`, default 120/min) is **decoupled** from the 10/min generate limit and MUST stay above the Gradio UI's ~24/min `/health`+`/models` polling — otherwise `/health` 429s and the UI shows "Disconnected / Server not running" (`is_server_running()` counts 200/503/429 as up; the UI badge does not). Read once at server import (`server/app.py`) — restart to apply. A global IP-keyed `SlowAPIMiddleware` + `default_limits` enforces the pre-auth ceiling on ALL routes (per-route `@limiter.limit` decorators run after `Depends(verify_auth)`, so without it unauthenticated floods bypass rate limiting); `enabled=not _RATE_LIMITING_DISABLED` on all four limiters makes the kill-switch global.

**Request body limit:** `RequestBodySizeLimitMiddleware` (pure-ASGI, `MAX_REQUEST_BODY_BYTES` ≈ 100 MB) rejects oversized bodies WITHOUT buffering — counts bytes off the ASGI `receive` callable, raises `HTTPException(413)` on overflow (pre-auth memory-DoS: an unauthenticated chunked body is never buffered to the cap before the 401); `Content-Length` fast-path rejects with no read. Starlette pinned `>=1.6.0,<2` (server extra). Native `max_body_size` (1.6.0+) is NOT a replacement: the custom middleware's pre-auth no-buffer ordering (registered before `security_headers`, outside CORS/`ExceptionMiddleware`), fast-path, and module-global patchable cap (`tests/test_body_size_limit.py`) are not equivalently provided.

**Streaming format:** `/generate-stream` returns length-prefixed binary chunks (`[sample_rate:4][length:4][payload:length]`). **Terminal error frame (WS2):** a mid-stream failure cannot use a status code (Starlette commits the 200 headers before the body iterates) and raising only truncates the connection — indistinguishable from a network drop — so the server emits a final frame with `sample_rate == 0` (`STREAM_ERROR_SENTINEL_SR`, never valid audio) whose payload is JSON `{"error", "code"}`; clients raise `TTSGenericError` on it rather than decoding it as float32. The format lives in ONE place — `core/stream_protocol.py` (no FastAPI/torch/mlx, so the CLI shares it): sentinel, 100 MB cap, `encode_stream_error_frame`, `iter_stream_chunks` parser used by the CLI **and** `TTSClient.generate_streaming`. Never re-fork it — the old duplicate drifted (public client decoded the JSON error payload as float32; caps differed 200 MB vs 100 MB). Guarded by `tests/test_stream_protocol.py` (anti-re-fork) + `tests/test_stream_error_frame.py`. `/ws` closes with RFC 6455 `1011` after its error message so a missed message is not read as a clean finish.

**Long-text chunking:** both `run_inference` and `run_inference_streaming` (all backends) split via `_prepare_text_chunks` (≤`max_chunk_chars`, default 500). Chunking is required: MLX `model.generate()` is capped by `max_tokens` @ 12.5 Hz and raising the cap was measured NO-GO on 16 GB (EOS-failure runaway loops + OOM — `docs/reviews/prf9-max-new-tokens-measurement-2026-08-15.md`). `_split_mlx_params` renames `max_new_tokens`→`max_tokens` at all 6 MLX call sites (ceiling `_MLX_MAX_TOKENS_CEILING`=4096); `_mlx_lang_code` passes `lang_code` on clone but `language` on custom/design (mlx-audio names differ). Chunks generate sequentially (~40–70 s each on MLX/M2 Pro), so: `TTSClient` non-streaming scales its read timeout via `_generation_timeout(len(text))` = `max(600, 0.25 s/char)` (`server/client/generator.py`) — never reintroduce a hardcoded `timeout=600`; `generate_via_server()` (the CLI's separate HTTP path) reuses the same helper on its batch's combined char count; streaming paths keep a flat 600 s (with `stream=True` it is an inter-chunk GAP timeout, not total time — both streaming clients). Server-side, `_stream_thread_join_timeout(text_len, max_chunk_chars)` (`app_generation.py`) scales the streaming inference-thread join — it must cover ONE chunk's generation or `inference_lock` releases while the model is still on the GPU; never a constant, and it applies to BOTH consumers (the `/ws` call site is pinned by `tests/test_streaming_thread_lifecycle.py::TestWsStreamJoinTimeout`). `0`/`None` disables chunking → the bound becomes the whole text.

**Environment independence — any Python env with test deps: `pip install -e ".[test]"`.** No conda required. Primary dev env: `qwen3-tts-mlx` conda env (M2 Pro, MLX backend) — development only.

**Reproducible installs:** `requirements.lock` pins the full `test+ui+dev` tree (regenerate after any pyproject dependency change: `python -m piptools compile pyproject.toml --extra test --extra ui --extra dev --output-file requirements.lock`). Platform extras (`mlx`, `torch`) are excluded — they conflict on `transformers` and live in separate conda envs. **Never install the lock into the platform conda envs** — it is for standalone test/CI envs only. The transformers/gradio conflict is env-specific: live in `qwen3-tts` (torch; transformers 4.57.3 needs `huggingface-hub<1.0`, lock's gradio 6.20 needs `>=1.2.0` → no gradio floor ≥ ~6.15 installable there), impossible in `qwen3-tts-mlx` (transformers 5.0.0rc3 + hub 1.5.0). Re-check both envs before trusting either half.

**Server restart rule:** always stop before starting to pick up code changes:
```bash
tts server stop && tts server start
```

**Run tests:**
```bash
python -m pytest tests/ -v --tb=short           # full suite; skips E2E by default (no hang)
python -m pytest tests/ -m e2e                  # opt-in E2E (needs live server)
python tests/run_batches.py                     # batch runner (hang-isolated), or --batch N / --list
python tests/run_full_suite.py --full --env {mlx,torch,all}   # multi-env; --test-type unit, --dry-run
make test-{core,voice,server,engine,optional,e2e} / make test-batch
```
2163+ tests across 108 modules. No GPU, models, or running server required (except E2E); auto-skip when optional deps are missing. E2E gating + live `/generate` rate-limit interaction: ARCHITECTURE.md ("E2E Gating and Rate Limiting").

**Test hygiene (enforced):** `async def test_*` on a plain `unittest.TestCase` never runs yet reports **ok** (plus a never-awaited RuntimeWarning) — use `unittest.IsolatedAsyncioTestCase` or `@pytest.mark.asyncio` outside a TestCase (pytest-asyncio is `strict`; unmarked coroutines are skipped). Statically guarded by `tests/test_async_test_hygiene.py`. New test modules MUST be registered in `BATCHES` in `tests/run_batches.py` (explicit list, not discovery) — enforced by `tests/test_batches_coverage.py` (absent from both `BATCHES` and the reason-carrying `INTENTIONALLY_UNBATCHED` allowlist = fail). `test_rate_limiting` + `test_e2e_*` are deliberately unbatched: the batch runner sets `TTS_DISABLE_RATE_LIMITING=1` and ignores pytest markers, so they would pass hollowly.

**Hung batches dump stacks:** `run_batch()` sends `SIGABRT` (child runs with `PYTHONFAULTHANDLER=1`) before `SIGKILL`, so a timeout reports every thread's traceback. Worth knowing: starlette's `TestClient` websocket `receive()` is unbounded — a `/ws` path that skips its terminal frame blocks a test forever regardless of test timeouts.

**Static gates:** `ruff check qwen3_tts tests` (`.ruff.toml`) · `mypy qwen3_tts/{core,server,interface}` (pyproject; vLLM excluded) · `bandit -r qwen3_tts -c pyproject.toml` (0 HIGH) · `make check-config-docs` (docs/CONFIG.md defaults vs `get_default_config()`). All ship in the `dev` extra.

**Log level:** `TTS_LOG_LEVEL` env var (default INFO; DEBUG for verbose). **Cap-warning field watch (#214 item 5):** `grep -n "token cap without emitting EOS" .voice_server.log*` — MLX-only (torch never emits it); any hit after #192 closed is a new lead, not a recurrence. **Warm-up skip:** `TTS_SKIP_WARMUP=1`. Inference-serialization details (warm-up, `/create-voice-prompt`, unload-asr, T5, `/transcribe`, torch auto-create-from-`.wav`): ARCHITECTURE.md ("Inference Serialization (#192 / #214)").

**Models & PM2:** HF model IDs in ARCHITECTURE.md. `tts server start/stop/restart` auto-detect PM2 supervision and delegate to `pm2 start/stop/restart` — a direct kill is indistinguishable from a crash (`autorestart: true` in `ecosystem.config.cjs` respawns it; a raw `stop` silently undoes itself), and a raw `start` over a registered app (even stopped) spawns a second, PM2-untracked daemon on the same port. `--public` is ignored under PM2 (edit `ecosystem.config.cjs`; the CLI warns). `--foreground` (Colab/notebooks) always bypasses PM2.
